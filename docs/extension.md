# Расширение-клиент: попап, defaults, проба качеств

Справочник по `client-extension/`. Роль расширения в системе — «глаза и руки»:
прочитать страницу, достать прямые ссылки, отправить задачи на сервер. Скачать
оно ничего не умеет и не должно.

Общий поток — в [`how-it-works.md`](how-it-works.md). Здесь — устройство
каждого файла и механизмы попапа.

---

## 0. Манифест (`manifest.json`)

MV3, без фонового скрипта — вся логика живёт в попапе, пока он открыт (кроме
сбора ссылок, который работает на вкладке). Права и зачем каждое:

| Право | Зачем |
|---|---|
| `activeTab` + `scripting` | Инъекция функций в страницу (`scripting.executeScript` с `world: 'MAIN'`) |
| `storage` | Настройки (адрес сервера/токен) в `storage.sync` + копия в `storage.local` |
| `declarativeNetRequestWithHostAccess` | Временное DNR-правило, чтобы проба качеств получила `Referer` (через `fetch` запрещённый заголовок не поставить) |
| `clipboardWrite` | Кнопка «копировать диагностику» |
| `host_permissions: http(s)://*/*` | Запросы и к любому серверу загрузок, и к CDN для пробы |

Версии: Chrome 111+, Firefox — `strict_min_version` в `browser_specific_settings`
(геко-id `idk-downloader-client@local`). Требование к Firefox поднималось, когда
появились свежие API — если обновляете расширение, браузер может попросить
подтвердить новое право.

## 1. Определение страницы и парсинг плеера (`popup.js`)

### `pageDetect` — что за страница открыта

Инъекция в MAIN world, которая:

1. смотрит URL (раздел сайта `/films/`, `/series/`, `/animation/`, `/cartoons/`,
   `/documentary/` — это будущая **категория** для медиатеки);
2. ищет в HTML вызов `sof.tv.initCDNMoviesEvents(...)` / `sof.tv.initCDNSeriesEvents(...)`
   и разбирает аргументы **устойчиво к порядку**: на зеркалах hdrezka количество
   и порядок аргументов различаются, поэтому парсится настоящий JS-вызов
   (свой сплиттер аргументов с учётом строк и скобок) и находятся значения по
   типам/позициям. Благодаря этому сериалы работают не только на
   hdrezka.ag/rezka.ag;
3. фолбэки из DOM: названия (`.b-post__title`), список озвучек
   (`.b-translator__item`), сезоны/серии из разметки — если конфиг плеера
   нечитаем.

Результат: `{type: 'film'|'serial'|…, id, translator_id, season, episode, favs,
is_camrip, is_ads, is_director, …}`. `favs` — антибот-токен сайта, без него
сайт вернёт отказ.

### `runInPage` — как всё исполняется

Единая обёртка над `scripting.executeScript({world: 'MAIN', func, args})`.
Функция уходит на страницу **целиком** и не может ссылаться на внешние
переменные — всё нужное передаётся аргументами. Это же ограничение делает
функции самодостаточными и удобными для тестов.

### `pageResolve` — запрос ссылок

Тот же POST `/ajax/get_cdn_series/` что и у сайта (см.
[`how-it-works.md`](how-it-works.md#шаг-3-получение-прямых-ссылок-резолв)),
исполняется **в контексте страницы**: `fetch` с `credentials: 'same-origin'`
берёт куки сайта, и Cloudflare пропускает запрос как «свой». Разбор ответа —
локальные парсеры попапа (переехали из старого проекта):

- `clearTrash` — сайт умеет прятать мусорные вставки в строке ссылок (часть
  строки «зашифрована» base64) — вычищается;
- `decodeVideoURL` — `[1080p]url1 or url2,[720p]url3` → `{quality: {urlsArr}}`;
- `decodeSubtitles` — `[Русский]url.vtt` + `subtitle_lns` (коды языков) →
  список субтитров с кодом и названием;
- `parseSeasons`/`parseEpisodes` — HTML-строки ответа (`data-season_id`,
  `data-episode_id`) в список сезонов.

## 2. Сбор ссылок по сериям: живёт на вкладке, а не в попапе

Для сериала на 200 серий попап пришлось бы держать открытым — а ссылки собираются
по одной серии за запрос. Поэтому цикл запускается **на самой вкладке**:

- попап создаёт «ожидаемую партию» и инъекцией запускает `pageCollectLinks(job)`,
  которая живёт в `window.__idkJob` на странице фильма;
- на каждую серию — свой POST `get_stream`, между сериями пауза 0.35 c (не
  долбим сайт), результат пишется в `window.__idkJob.results`;
- попап опрашивает `window.__idkJob` раз в 0.7 с (`JOB_POLL_MS`) и рисует
  «Собираем ссылки: 7 из 200». **Попап можно закрыть** — цикл продолжится;
- вернувшись, попап подхватывает прогресс (`resumeCollectJob`); если сбор уже
  закончился — сразу отправляет задачи на сервер (`sendCollectedJob`);
- отмена и «отправлено» пишутся обратно в тот же объект. Ограничение одно:
  вкладка со страницей фильма должна остаться открытой (ссылки берутся из её
  сессии) — если вкладку обновить/закрыть, партия прервётся.

## 3. Правила выбора по умолчанию (`defaults.js`)

Отдельный файл с **чистыми функциями** (ни DOM, ни `chrome.*`) — поэтому он
покрыт тестами целиком. Что попап выбирает сам, чтобы вы не трогали поля:

- **Озвучка — дубляж** (`pickVoiceover`): ранжирует озвучки — обычный дубляж
  (лучший) → премиумный дубляж (у него бывает заглушка вместо файла) → дубляж
  не на русском (украинский и т.п. по умолчанию не нужен) → не дубляж
  (не подходит вовсе). Если дубляжа нет — берётся та озвучка, что выбрана на
  сайте. hdrezka часто ставит активной свою («HDrezka Studio»), а дубляж лежит
  ниже — раньше приходилось переключать руками. Вместе с озвучкой берутся её
  флаги camrip/ads/director (без них сайт вернул бы файл чужого перевода).
- **Качество — «1080p Ultra», иначе «1080p»** (`pickDefaultQuality`): выше
  1080p сам не поднимается (2K/4K — другой вес файла; в списке остаются,
  выбрать руками можно). Если FullHD-класса нет — ближайшее снизу
  (`pickQuality`: точное → самое тяжёлое не выше желаемого → самое низкое).
  Последний шаг для серий с бедным набором: лучше чуть хуже, чем никак.
- **Субтитры — русские и включены сразу** (`pickSubtitleLang`): ищет русский
  по коду от сайта (`rus`/`ru` из `subtitle_lns`), а если кода нет — по
  названию («Русский», «Русские (форсированные)», «Russian»). Русских нет —
  галочка не ставится (украинские к русской озвучке ни к чему). Снятая
  пользователем галочка или выбранный вручную язык попапом не перебиваются.
- **Проба — только 720p+** (`shouldProbe`): 360p/144p — мусор, а каждая проба
  это Range-запрос. Подписи без числа («SD») тоже не пробуются.
- Вспомогательное: `qualityWeight` (сравнение качеств: «4K» ≈ 2160 × 630,
  «Ultra» чуть тяжелее обычного), `sortQualities`, `claimedHeight`
  («1080p Ultra» → 1080, «4K» → 2160).

Модуль оформлен как IIFE, которая и в `module.exports` (для тестов в Node), и в
`globalThis.HdzgDefaults` (для попапа — классический скрипт без сборки).

## 4. Проба качеств (`media-probe.js`)

Тоже самодостаточный IIFE (`globalThis.HdzgProbe`, тот же dual-export). Задача:
для списка ссылок одного качества вернуть `{bytes, width, height, codec, …}`.

Как работает:

1. **Первый запрос — Range на 128 КБ** (`HEAD_BYTES`). Из `Content-Range`
   достаётся полный вес файла. Дальше разбор MP4: боксы читаются по цепочке
   (размер+тип) до `moov`, в нём — `stsd`, где лежат кодеки и
   ширина/высота. Если `moov` не уместился в первое окно (у длинных файлов он
   в конце), дочитываются следующие окна (лимит 2 МБ) и «шапка» следующего
   бокса (4 КБ) — запросов немного, а полные вес и разрешение есть.
2. **HLS**: если ссылка — `.m3u8`, берутся `RESOLUTION`/`BANDWIDTH` из
   мастер-плейлиста. Вес получается прикидочный (битрейт × длительность) — в
   интерфейсе помечается «вес примерный (HLS)».
3. **Заголовки**: запрос идёт из контекста расширения (CORS не мешает), но
   CDN требует `Referer` страницы — на время запроса ставится сессионное
   DNR-правило (`modifyHeaders`) и снимается сразу после ответа
   (`withMediaHeaders`). Без этого CDN отвечает 404.
4. **Кэш** в `storage.local`, ключ `idk-probe-cache`, TTL 12 часов, максимум
   300 записей. Ключ кэша — сама ссылка: после перезагрузки страницы ссылки
   новые (подписанные), кэш честно промахивается и проба идёт заново. Так что
   кэш — защита от повторных проб в рамках сессии, а не источник устаревших
   данных.
5. `probeQuality` пробует ссылки качества по очереди/параллельно
   (`probeCandidates`) — у качества может быть несколько зеркал.

Результаты попадают в UI: `1080p [720p] 1.1 GB`, вердикт подкоробки
(оранжевая — внутри меньше, зелёная — больше), подсказка «В файле 1920×1080 ·
H.264 · 1.13 GB». И в задачу: `total_bytes` (сервер использует как ожидаемый
вес до старта) и `real_width`/`real_height` (веб-морда покажет `1080p → 720p`,
если подпись врёт).

## 5. Попап: что ещё там есть

- **Настройки сервера**: адрес + токен в `storage.sync` **и** копия в
  `storage.local`; при загрузке побеждает копия с более свежим `updatedAt`
  (`readStoredSettings`). Включён синк — настройки едут с профилем браузера,
  выключен — работает локальная копия.
- **Строка состояния сервера** внизу: свободно/нужно, папка (`saveDir`), ffmpeg,
  занятые слоты — из опроса `/api/state` раз в 3 секунды (`POLL_MS`), только
  когда попап виден.
- **Управление очередью прямо в попапе**: у каждой задачи пауза/продолжить/
  отменить/повторить, в шапке — «Остановить» и «Возобновить» (подтверждение
  вторым кликом), блок «На сервере» сворачивается и запоминает состояние.
- **Проверка места перед отправкой** (`spaceCheck`): вес выбранного качества ×
  число серий против `needBytes`. Не влезает → первый клик показывает
  предупреждение, кнопка становится «Всё равно скачать». После отправки сервер
  присылает свежий `space` и попап повторяет предупреждение, если не сошлось.
- **«Уже скачивалось»** (`checkAlreadyDownloaded`): сводка `GET /api/movies/:id`
  + предупреждение о перезаписи + кнопка **«Отменить этот фильм»** (двухкликовое
  подтверждение) → `POST /api/movies/:id/cancel`.
- **Ручной выбор серий**: сетка с переключателем сезона и чипами, «Выбрать все»/
  «Снять»; незагруженный сезон подтягивается сам. Плюс «Весь сериал» (по
  умолчанию, со счётчиком «К отправке: N серий (M сезонов)»), текущий сезон,
  текущая серия.
- **«Только субтитры»**: отправляет одни субтитры для выбранных серий — когда
  видео уже скачано, а субтитры пропустились.
- **Протухшие ссылки**: имя задачи — ссылка на страницу-источник (`referer`);
  у сбойной задачи с ошибкой 4xx — подсказка «откройте страницу и отправьте
  заново» (`looksExpired`).
- **Диагностика** (значок копирования): в буфер уходит весь разбор — тип
  страницы, параметры, последний ответ сайта, пробы качеств, место, состояние
  фонового сбора, текст ошибки. Её можно прислать разработчику.
- Поле выбора качеств — **свой контрол**, а не `<select>`: в `<option>` нельзя
  вставить бейдж с весом/подкоробкой; панель сама открывается вверх, чтобы не
  обрезаться краем попапа.

## 6. Тесты

```bash
node client-extension/test/defaults.test.mjs  # правила выбора: дубляж, качество, субтитры, проба
node client-extension/test/popup.test.mjs     # проводка попапа целиком
node client-extension/test/probe.test.mjs     # разбор MP4/HLS (нужен ffmpeg)
```

- `defaults` — чистые функции `defaults.js`: какой дубляж победит (и почему
  премиумный/украинский позже), качество по умолчанию, что попадает в пробу,
  что берётся вместо пропавшего качества, какой язык субтитров «русский».
- `popup` — настоящие `popup.js` и `defaults.js` в песочнице Node (`vm` + мини-DOM
  + стабы `chrome.*`): ссылки запрашиваются у дубляжа; «1080p Ultra» стоит в
  списке; пробы только у 720p+; субтитры сразу включены и на русском (снятую
  галочку не возвращают); при отсутствии ссылок у дубляжа — откат на озвучку
  сайта; «Отменить этот фильм» шлёт запрос только после подтверждения.
- `probe` — генерирует ffmpeg'ом файлы разных разрешений (moov в начале/конце,
  HEVC, портретное видео, аудио перед видео), поднимает локальный HTTP-сервер
  и проверяет, что проба верно читает вес/разрешение, переживает битые ссылки и
  серверы без поддержки `Range`. В сеть не ходит.
