# Документация проекта — начните здесь

> Это документация «на пальцах»: объясняет, как проект устроен и как он работает,
> от большого вида до отдельных функций. Читается сверху вниз — каждая следующая
> глава опирается на предыдущую, но и по отдельности их читать можно.

## Что это вообще такое — в двух абзацах

Вы смотрите фильм/сериал на сайте (сейчас — hdrezka и её зеркала) и хотите
**скачать его не на ноутбук, а на свой домашний сервер** — чтобы файлы сразу
лежали в медиатеке Jellyfin и были доступны, когда ноутбук выключен.

Проект состоит из двух частей, которые общаются по HTTP:

- **Расширение для браузера** (`client-extension/`) — «глаза и руки». Оно живёт на
  странице фильма в вашем браузере, читает данные плеера, выпрашивает у сайта
  прямые ссылки на видео/субтитры (используя **вашу** сессию — поэтому Cloudflare
  и антибот ему не мешают) и отправляет эти ссылки на сервер.
- **Сервер загрузок** (`server/`) — «рабочий». Принимает задачи, ставит их в
  очередь (SQLite), качает файлы сам, раскладывает по папкам по шаблонам имён и
  показывает веб-морду с прогрессом. Браузер после отправки задач можно закрыть.

Никаких npm-зависимостей ни там, ни там: сервер — чистый Node.js ≥ 22.5 со
встроенным `node:sqlite`, расширение — ванильный JS без сборки.

## Схема проекта за 30 секунд

```
 ┌─────────────────── ваш браузер ───────────────────┐
 │                                                   │
 │  вкладка hdrezka ──► расширение (попап)           │
 │      │                    │                       │
 │      │ DOM, плеер sof.tv  │ ссылки на видео       │
 │      └──► сессия сайта ───┤ (mp4/m3u8/vtt)        │
 │                           │                       │
 └───────────────────────────┼───────────────────────┘
                             │ POST /api/tasks
                             ▼
 ┌───────────── ваш сервер (Node.js) ────────────────┐
 │  REST API  ──► очередь в SQLite ──► воркеры       │
 │      ▲                        │                   │
 │      │             HTTP GET к CDN (Range, докачка)│
 │      │                        ▼                   │
 │  веб-морда          файлы на диск:                │
 │  (poll 1 раз/с)     медиатека/Фильмы/             │
 │                     «Название (2022)/Название.mp4» │
 └───────────────────────────────────────────────────┘
```

## Словарик (слова, которые встречаются в коде и доках)

| Слово | Что значит |
|---|---|
| **Задача (task)** | Одна строка в БД сервера: «скачай вот эту ссылку в вот такой файл». Один файл = одна задача. Сериал на 20 серий с субтитрами = 40 задач |
| **Прямая ссылка** | URL самого файла (`.mp4`, `.m3u8`, `.vtt`), а не страницы. Только такие ссылки сервер и умеет качать |
| **Резолв** | Процесс «страница → прямые ссылки». Делает расширение в контексте страницы (сервер не умеет: сайт отдаёт ему антибот-страницу) |
| **Проба качества (probe)** | Range-запрос на первые 128 КБ файла: узнать полный вес и реальное разрешение видео (hdrezka подписывает «1080p», а внутри может быть 720p) |
| **Referer** | Адрес страницы-источника. CDN требует его в заголовке запроса, а ещё по нему можно вернуться за свежей ссылкой, когда старая протухла |
| **Медиатека (library)** | Корневая папка для Jellyfin. Если задана — файлы качаются сразу в неё по категориям (`films = Фильмы` и т.п.); иначе — в папку загрузок |
| **`.part`-файл** | Временный файл недокачанной задачи: `Фильм.mp4.42.part` (42 — id задачи). Докачивается Range-запросом после паузы/рестарта |
| **Группа (group)** | Задачи одного фильма/сериала на экране: фильм → серия → файлы. Группируются по `movie_id` и `group_key` |
| **MAIN world** | Контекст страницы сайта (в отличие от изолированного мира расширения). Оттуда доступны куки сайта и jQuery страницы — потому запросы к сайту делаются именно оттуда |
| **DNR** | `declarativeNetRequest` — API расширения, которым на время запроса подставляется заголовок `Referer` (через обычный `fetch` его поставить нельзя) |
| **idk/hdzg** | Префиксы внутренних ключей расширения. Новые — `idk-server-settings`, `idk-server-ui`, `idk-probe-cache`, `window.__idkJob`; старые `hdzg-*` читаются один раз как миграция настроек |

## Быстрая шпаргалка «где что лежит»

```
client-extension/
  manifest.json     — манифест MV3 (права, версии браузеров)
  popup.html/js/css — весь попап (UI + логика, ~2600 строк, без сборки)
  defaults.js       — правила «что выбрать по умолчанию» (чистые функции, тестируются)
  media-probe.js    — проба веса/разрешения (Range + разбор MP4, без зависимостей)
  test/             — 3 набора тестов (node --test, стабы chrome.*/DOM)

server/
  src/
    index.js        — точка входа: CLI-гейт, рестарт-восстановление, запуск всего
    config.js       — CLI-аргументы и переменные окружения
    db.js           — SQLite: таблицы, миграции, очередные запросы
    tasks.js        — приведение входящей задачи к виду БД + имя файла
    util.js         — шаблоны имён, санитайзинг, словарь языков субтитров
    downloader.js   — пул воркеров, HTTP-докачка, HLS через ffmpeg, паузы/отмены
    estimate.js     — «сколько ещё места нужно очереди»
    api.js          — REST-роутер, статика, CORS, токен
    logger.js       — цветные логи и баннер
  public/           — веб-морда (index.html + app.js + styles.css, ванильный JS)
  test/             — node --test (estimate, db, cancel-movie)
  deploy/           — systemd-юнит для систем без NixOS

nix/                — пакет + NixOS-модули (см. корневой README)
```

## Как проверить, что всё работает (после любых правок)

```bash
cd server && npm test                      # тесты сервера (node --test)
node client-extension/test/defaults.test.mjs   # правила выбора по умолчанию
node client-extension/test/popup.test.mjs      # проводка попапа (песочница)
node client-extension/test/probe.test.mjs      # проба качеств (нужен ffmpeg)
cd .. && node server/src/index.js --port 8080  # ручной прогон
```
