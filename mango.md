# Mango: манга в idk-downloader

> Рабочий документ по манга-подсистеме. Здесь — правила имён и папок, архитектура
> источников, статус реализации и то, что ещё не сделано. Технические детали
> сервера — в [`docs/server.md`](docs/server.md), история исследований — в
> [`prototypes/mango/research.md`](prototypes/mango/research.md).
>
> Коротко: **com-x.life, MangaDex и MangaLib уже работают** (очередь, папки,
> история, веб-морда, языковые чипы MangaDex). MangaLib сделан как обычный
> HTTP-адаптер: браузер ему не нужен. Chromium остаётся только для com-x.life и
> запускается лениво, на время разбора страницы — не при старте `node`.
>
> **Что показала разведка (27–28.10.2026):** MangaDex API работает без VPN и без
> токена — русские главы, обложки и страницы доступны; есть внешние главы,
> дубли групп и лимит ~5 req/s. MangaLib API (`api.imglib.info/api`, резерв
> `api.cdnlibs.org/api`) отвечает с `site-id: 1` и браузерными заголовками;
> картинки — `img3.cdnlibs.org` и зеркала из `/constants`. DDoS-Guard может
> вернуть 403, но для API это не постоянное требование; headless Chromium как
> fallback пока не включаем. Лучший референс по MangaLib — DownloadLib.

## 1. Что хотим получить

Качалка манги, которая:

- принимает ссылку на тайтл (а не требует ручной возни с главами);
- качает выбранные главы **пачкой**, без вопросов «куда», «как назвать», «какой формат»;
- раскладывает страницы в обычные папки, которые читает любая читалка;
- не трогает содержимое после скачивания — юзер сам удаляет рекламные страницы
  переводчика, спойлеры и т.п.;
- не пишет рядом с контентом служебные файлы;
- умеет несколько источников, но хранит всё в одном дереве.

Кодовое имя подсистемы — **mango** (так исторически сложилось), в интерфейсе —
«Манга».

### Принципы

1. **Меньше вопросов при добавлении.** Юзер качает пачками, а не по одной главе.
   Нажал «Скачать» — уехало в очередь. Название, год и номера берём с источника,
   а не спрашиваем.
2. **После скачивания программа не трогает содержимое.** Страницы с рекламой
   бывают в начале, середине и конце, с разным количеством; автоматически их не
   отличить, а vision-модель дорогая и с overhead. Поэтому downloader кладёт
   страницы как есть и никогда не перепроверяет и не дописывает готовые папки.
3. **Никаких служебных файлов рядом с контентом.** Ни `.complete`, ни
   `ComicInfo.xml`, ни кэша внутри папки тайтла. Состояние (что скачано, откуда,
   что пропущено) — в SQLite сервера.
4. **Обложку кладёт юзер.** На сайтах она часто всратая (144p), а нормальную
   находишь на wayback machine или где-то ещё. `Cover.png` в папке тайтла —
   территория юзера: программа его не создаёт, не проверяет и не удаляет.
5. **Живые папки, не CBZ.** Юзеру нужно редактировать страницы; архив только
   мешает.
6. **Один тайтл — одна папка в рамках источника.** Если тот же тайтл качают
   с другого источника, автоматически по названию не склеиваем: можно смешать
   разные переводы/выпуски. Источник хранится в БД, а не в имени папки;
   осознанное слияние — отдельная операция (см. «Ключи и папки»).

## 2. Структура папок

```
{Название} [{год}]/
├── Cover.png                  ← кладёт юзер, программа не проверяет
├── Volume 1/
│   ├── 8 - яблоко зеленое сорванное название/
│   │   ├── 000.png
│   │   ├── 001.jpg
│   │   └── 002.png
│   └── 2.5 - Экстра/
│       └── 000.png
└── Volume 2/
    └── 12/                    ← у главы нет названия → папка без названия
        └── 000.png
```

### Папка тайтла

`{Название} [{год}]`, например `Суи и Нери с закатной планеты [2020]`.

- `{Название}` — **русское** название. На ComX это `h1.flex-grow-1`; оно есть
  всегда, в отличие от английского `h2.page__title-original`.
- Английское и альтернативные названия (`page__alt-names`) **не используем** —
  незачем. Для MangaDex, если русского названия нет, берём русский
  `altTitle` или английское название (см. раздел про адаптеры); остальные
  альтернативы в имя папки не тащим.
- `[год]` — квадратные скобки, не круглые: юзеру так красивее. Года нет →
  папка просто `{Название}` без скобок.
- Название и год санитайзятся: `/ \ : * ? " < > |` и управляющие символы
  заменяются/выкидываются, хвостовые точки и пробелы срезаются, длина сегмента
  ~150 символов. Это нужно, чтобы папка пережила Windows/NAS/ТВ.
- Если папка с таким именем уже занята **другим** тайтлом — добавляем суффикс
  ` 2`, ` 3` (первый свободный). Одинаковый тайтл с тем же источником — та же
  папка.

### Папка тома

`Volume N`, где `N` — том с источника. Нет тома → `Volume 1` (структуру держим
однородной; оншоты и главы без тома не вываливаются в корень).

### Папка главы

`{номер}` или `{номер} - {название}`:

| строка на сайте           | папка                                  |
|---------------------------|----------------------------------------|
| `1 - 8`                   | `Volume 1/8`                           |
| `1 - 2.5 Экстра`          | `Volume 1/2.5 - Экстра`                |
| `1 - 5 5 лет спустя`      | `Volume 1/5 - 5 лет спустя`            |
| `1 Кому улыбнётся мир?`   | `Volume 1/1 - Кому улыбнётся мир?`     |
| `1 - 8-9`                 | `Volume 1/8-9`                         |

Правила:

- На ComX разделитель тома и главы — **`« - »` с пробелами**. До него том,
  после — номер (старшая числовая часть с точками) и опциональный хвост-название.
- Главы без тома (оншоты, строка `1 Название`): номер = числовая часть,
  название = хвост, папка = `Volume 1/...`. Случай редкий: почти у всех есть
  хотя бы `1 - 1`.
- Названия у главы нет → папка — просто номер, без дефиса.
- Номер не дополняем нулями (`8`, а не `008`): сортировку держит натуральная
  сортировка проводника. Дробные номера (`2.5`) сохраняем как есть.
- `8-9` (две главы в одном выпуске) трактуем буквально — папка `8-9`.
- Номер отсутствует вообще (например, ваншот в MangaDex с `chapter: null`) —
  используем `1`; если в названии есть свой номер, он попадёт в хвост.
- Папка главы тоже санитайзится по тем же правилам, что и папка тайтла.

### Файлы страниц

- `000.png`, `001.jpg`, `002.webp` — нумерация с `000`, расширение **по
  фактическому `Content-Type`**, а не по URL.
- ComX CDN перекодирует всё в WebP (URL с `.jpg` отдаёт `image/webp`, magic
  bytes `RIFF…WEBP`). Оставить `.jpg` у webp-байтов — грязно, часть читалок
  спотыкается. Поэтому расширение берём из ответа.
- Нулей до 3 цифр; если страниц ≥ 1000 — до 4 (количество известно до
  скачивания).
- Порядок страниц — как в данных источника; нумеруем по индексу, а не по
  исходному имени файла.
- Ничего не перекодируем и не оптимизируем: кладём ровно байты, которые отдал
  CDN.

## 3. Архитектура: источники как адаптеры

Сейчас `server/src/mango/index.js` — общий пайплайн с развилкой по `source`:
ComX (`comx.js` + `browser.js`), MangaDex (`mangadex.js`), MangaLib
(`mangalib.js`). Полного реестра адаптеров пока нет, но всё, что специфично для
источника, живёт в его модуле: разбор URL, метаданные, список глав и страницы.
Общий код не знает про `window.__DATA__`, MangaDex UUID или MangaLib slug.

### Контракт адаптера (предложение)

```js
{
  id: 'comx',                    // стабильный id для БД и UI
  label: 'com-x.life',

  matches(url),                 // принимаем ли такую ссылку
  normalize(url),               // канонический URL (зеркала → основной)

  async resolve(url) {
    return {
      source: 'comx',
      seriesKey: 'comx:26588',   // стабильный ключ тайтла
      url,                       // страница-источник
      title,                     // русское название для папки
      year,                      // '2020' | null
      folder,                    // 'Название [2020]' (уже санитайзено)
      chapters: [{
        id,                      // id главы на источнике
        volume,                  // '1' | null → '1'
        number,                  // '8', '2.5', '8-9'
        title,                   // 'Экстра' | ''
        language,                // 'ru' | 'en' | ...
        group,                   // сканлейт-группа (MangaDex)
        url,                     // ссылка на главу (для истории/ручного открытия)
        external,                // true → скачать нельзя, есть externalUrl
        unavailable,             // true → нет страниц/лицензия/платно
      }],
    };
  },

  async images(info, chapter) {
    return {
      referer,                   // Referer для картинок
      headers,                   // дополнительные заголовки, если нужны
      images: [{
        urls: [url1, url2],      // зеркала/хосты в порядке попыток
        ext,                     // подсказка, если Content-Type врёт
      }],
    };
  },
}
```

Общий пайплайн:

- `resolve` — один раз на добавление (браузер/HTTP — внутри адаптера);
- `images` — на каждую главу;
- скачивание, нумерация, `.idk-part`, ретраи, БД, UI — общие.

Что важно не протащить в общий код: `window.__DATA__`, `news_id`, DleGuard,
MangaDex UUID, MangaLib slug. Всё это — детали адаптера.

### Выбор источника

- По URL: `com-x.life` / `ru.com-x.life` → ComX; `mangadex.org` →
  MangaDex; `mangalib.me` / `mangalib.org` → MangaLib.
- В UI можно оставить выпадающий список «Источник» (сейчас он есть, но
  фактически один), а можно определять автоматически и показывать бейдж.
  Лучше автоматически: меньше вопросов юзеру, принцип 1.
- Неизвестный URL → понятная ошибка со списком поддерживаемых источников.

### Ключи и папки

- `seriesKey`: `comx:{news_id}`, `mangadex:{uuid}`, `mangalib:{id}`.
- Стабильная папка тайтла хранится в БД (`mango_series`), а не пересчитывается
  каждый раз из названия. Иначе переименование тайтла на сайте разбросает
  главы по двум папкам.
- Если папка занята другим `seriesKey` — суффикс. Если тот же `seriesKey` —
  используем сохранённую папку, даже если название на сайте поменялось.
- Кросс-источниковое слияние (ComX + MangaDex + MangaLib) **не автоматическое**:
  у источников разные id, названия и составы глав. Если юзер хочет один тайтл
  в одной папке — это ручное указание «объединить с…», а не эвристика по
  названию. Иначе легко получить `8` из двух переводов в одной папке.

## 4. ComX (com-x.life) — работает

### Что уже сделано

- `server/src/mango/comx.js` — разбор ссылок, `window.__DATA__` → страницы,
  скачивание картинок с перебором хостов и ретраями, расширение по
  `Content-Type`.
- `server/src/mango/browser.js` — headless Chromium через `puppeteer-core`
  (тонкий клиент к системному браузеру, не Selenium): ленивый запуск,
  постоянный профиль рядом с БД, скрытый `navigator.webdriver`, один браузер
  на все разборы, очередь `exclusive`.
- `server/src/mango/naming.js` — чистые правила имён, покрыты тестами.
- `server/src/mango/index.js` — задания, очередь, прогресс, пауза/отмена,
  удаление тома/произведения, история в SQLite.
- Веб-морда: вкладка «Манго», вставка ссылки, выбор глав по томам, очередь,
  история, удаление томов.
- API: `POST /api/mango/resolve`, `POST /api/mango/download`,
  `GET /api/mango/jobs`, `GET /api/mango/jobs/:id`, `GET /api/mango/history`,
  пауза/возобновление/отмена/удаление по `seriesKey`.

### Как получаются данные

- Сайт на DLE с антиботом **DleGuard**: первый запрос редиректит на `/_c?t=...`,
  после JS-челленджа ставится cookie `__guard_trust`. Публичного API нет.
- **HTML-страницы серверным fetch/curl не читаются**: DleGuard тарпитит запрос
  по таймауту, даже с cookies и заголовками Chrome. Поэтому страницу тайтла и
  читалку открывает headless Chromium; он проходит челлендж сам, без логина.
- Из `window.__DATA__` на странице тайтла: название (из `h1.flex-grow-1`), год
  (инфоблок `Год:`), главы (`chapters[]` с `id`, `title`, `posi`).
- Из `window.__DATA__` на странице читалки: `host`, `host_ru`, `images[]`.
- Картинки: `https://{host}/comix/{path}`, host из `__DATA__`
  (`img.com-x.life` / `rus.com-x.life`), с `Referer` на страницу главы.
  DleGuard картинки не охраняет — обычный `fetch` с браузерным `User-Agent` и
  `Accept: image/...`.
- Rate limit: ~3 запроса/сек; картинки качаем последовательно с паузой.

### Подводные камни (проверено)

- Без `Accept: image/...` хост `rus.com-x.life` молча подвешивает запрос до
  таймаута; с полными заголовками отвечает.
- `img.com-x.life` (Cloudflare) стабильнее, `rus` — запасной. Хост не
  хардкодим, берём из `__DATA__`.
- Chromium нужен только на момент разбора страницы, не во время скачивания.
- Профиль браузера (`server/data/mango-chromium-profile`) переживает
  перезапуски: сессия DleGuard сохраняется.
- Если DleGuard однажды начнёт палить headless — запасной путь: расширение
  достаёт те же данные из вкладки юзера (как у hdrezka). Контракт адаптера
  один и тот же.

### Пример живого прогона

Глава `1 - 1` «Суи и Нери с закатной планеты [2020]» — 27 страниц WebP
1200×1707 в `.../Volume 1/1/000.webp…026.webp`; повторный запуск — «уже есть»;
глава без данных читалки — понятный провал без мусора на диске.

## 5. MangaDex — адаптер (работает)

### Почему отдельный адаптер

MangaDex — официальный открытый API, без HTML и антибота. Ему не нужен
Chromium: `resolve` и `images` могут работать на обычном `fetch`. Это самый
дешёвый источник по инфраструктуре, но со своими правилами (языки, группы,
внешние главы, лицензирование).

> У автора `mangadex.org` блокируется, а `api.mangadex.org`,
> `uploads.mangadex.org` и `*.mangadex.network` — нет. Поэтому адаптер **не
> делает ни одного запроса к mangadex.org**: только API и CDN. Ссылку
> `mangadex.org/title/...` он разбирает как строку и идёт на API.

### Проверено на живом API (27.10.2026)

Без токена, обычным `curl` из текущего окружения:

- `GET https://api.mangadex.org/manga?title=...&limit=1` → `data[].id`,
  `attributes.title` (map языков), `altTitles`, `year`,
  `availableTranslatedLanguages`, `relationships` (в т.ч. `cover_art`).
  Пример: `b5e36871-1708-41e4-9a1b-b380abf1a19e` —
  «Tasogare-Boshi no Sui to Neri», 2020, русские главы есть, `title.ru` нет
  (важный случай: папка получит английское имя).
- `GET /manga/{id}/feed?translatedLanguage[]=ru&order[volume]=asc&order[chapter]=asc`
  → `total`, `data[]` с `volume`, `chapter`, `title`, `translatedLanguage`,
  `externalUrl`, `isUnavailable`, `pages`, `publishAt`; в `relationships` —
  `scanlation_group`, `manga`, `user`.
  - `includes[]=scanlation_group` добавляет имя группы (`NekoFun BlackMarket`).
  - Без `includes` есть только UUID группы.
- `GET /at-home/server/{chapterId}` → `baseUrl`, `chapter.hash`,
  `chapter.data[]`, `chapter.dataSaver[]`. URL:
  `{baseUrl}/data/{hash}/{filename}` (оригинал) или
  `{baseUrl}/data-saver/{hash}/{filename}` (сжатое).
  Пример: глава 1 «Суи и Нери» — 27 страниц, hash
  `9a2434eeb5eab76acf1327e2d4beaae0`.
- `GET /chapter/{chapterId}?includes[]=manga&includes[]=scanlation_group` —
  резолв ссылки на главу в мангу и группу.
- Обложка: `GET /cover/{coverId}` → `attributes.fileName`; URL
  `https://uploads.mangadex.org/covers/{mangaId}/{fileName}` (200,
  `image/jpeg`, без авторизации). `.512.jpg`/`.256.jpg` — уменьшенные версии.
- Внешние главы: у «Jujutsu Kaisen» (`c52b2ce3-7f95-469c-96b0-479524fb7a1a`)
  все 5 английских глав имеют `externalUrl` на MangaPlus и `pages: 0` —
  скачать нельзя.
- Дубли: у «Kaguya-sama» на номера 2-15, 2-16, 3-21, 3-22 по две группы с
  разным количеством страниц (17/19, 9/8). Значит, дедуп по номеру обязателен.

### API и ограничения

- API v5, OpenAPI 5.13.1; ключ для обычного чтения не нужен.
- Глобальный rate limit — **~5 запросов/сек на IP** (не точное значение).
  При 429 нельзя долбить: будет временный 403-бан на весь `*.mangadex.org`.
- `GET /at-home/server/{id}` — отдельный лимит **40 запросов/мин**.
- `offset + limit > 10 000` отклоняется; `limit` обычно ≤ 100 (у feed бывает
  500). Значит, пагинация по `offset`, пока `data.length === limit` и
  `offset < total`.
- `includeExternalUrl`, `includeEmptyPages`, `includeUnavailable` — это
  **фильтры** («только external/пустые/недоступные»), а не «включить». Мы их
  не передаём: нужны обычные главы и external, которые помечаем в UI. Если
  передать `includeExternalUrl=1`, у обычного тайтла feed внезапно станет
  пустым — проверено.
- `User-Agent` обязателен и не должен врать; `Via` запрещён.
- `baseUrl` живёт **15 минут**; после 403/истечения — заново
  `GET /at-home/server/{id}`.
- Для картинок с `mangadex.network` (не `*.mangadex.org`) нужно отправлять
  отчёт `POST https://api.mangadex.network/report` с `{url, success, bytes,
  duration, cached}`. Это требование MangaDex@Home, не опция.
- Авторизационные заголовки **нельзя** отправлять на `uploads.mangadex.org`
  и `*.mangadex.network` — картинки от этого отклоняются.
- OAuth2: personal client (password flow) — только для своего аккаунта; public
  clients ещё не доступны. Обычный русский каталог и at-home в тесте работали
  **без токена**. Нужен ли токен для 18+/restricted — не проверено; на старте
  можно не поддерживать restricted.
- AUP: обязательна атрибуция MangaDex и сканлейт-групп; нельзя строить
  платный/рекламный сервис.

### Реализовано

- `server/src/mango/mangadex.js` — API-клиент, feed, at-home, картинки,
  отчёт MangaDex@Home, языки, дедуп групп.
- `server/src/mango/index.js` — развилка `comx` / `mangadex`, общий
  `finalizeInfo`, общий пайплайн.
- `server/src/mango/naming.js` — суффикс языка у папки главы.
- `server/src/db.js` — колонки `source`, `language`, `group_name`,
  `chapter_url`, `is_external` + миграция.
- Веб-морда — чипы языков, бейджи «на сайте» / «недоступно», source в
  карточке.
- Тесты — `server/test/mangadex.test.mjs`, миграция в `server/test/db.test.mjs`.

### Решения

1. **Язык.** Реализовано: набор приходит из `availableTranslatedLanguages`,
   в UI — чипы. По умолчанию `ru`, если его нет — `en`, иначе первый язык,
   у которого есть скачиваемые главы. **Один язык на задание.** Главы не на
   русском получают суффикс `[en]` в папке главы (`1 [en]`), поэтому ru/en
   не смешиваются. Смена чипа переразбирает тайтл и сбрасывает выбор глав.
2. **Дубли групп.** Группируем по `volume + chapter + language`, оставляем
   одну: сначала не-external/доступную, потом с большим `pages`, потом самую
   раннюю. В UI пока одна строка с именем выбранной группы в tooltip.
   Приоритет «больше страниц» — эвристика, открытый вопрос.
3. **Внешние/недоступные главы.** `externalUrl != null` → «на сайте», не
   выбирается. `pages: 0` без external → «недоступно». `isUnavailable` тоже
   обрабатывается, если API его отдаст.
4. **`volume: null`.** Кладём в `Volume 1`, как и ComX.
5. **`chapter: null` (ваншот).** Номер `1`, название — из `title`.
6. **Название тайтла.** `title.ru` → первый `altTitles[].ru` →
   `title.en` → `altTitles[].en` → `title[originalLanguage]` → первый
   доступный. Для «Суи и Нери» это даст английское имя, потому что русского
   `title`/`altTitle` на MangaDex нет — это нормально, не выдумываем перевод.
7. **Год.** `attributes.year`; нет — папка без скобок.
8. **Обложка.** Не качаем (принцип 4), хотя API её отдаёт.
9. **Атрибуция.** В БД хранятся `chapter_id`, `group_name`, `language`,
   `chapter_url`; в UI показывается источник и группа в tooltip.

## 6. MangaLib — адаптер (работает)

### Проверено на живом API (28.10.2026)

API: `https://api.imglib.info/api`; резерв — `https://api.cdnlibs.org/api`.
Сайт: `mangalib.me` / `mangalib.org`.

- Голый `curl` без заголовков → **403** от DDoS-Guard. С `site-id: 1`,
  `Referer: https://mangalib.me/` и нормальным `User-Agent` → **200 JSON**.
  `Origin` не обязателен. Node-fetch с этими заголовками тоже работает.
- `GET /api/manga?q=...&site_id[]=1` — поиск. Параметр именно `q`; `search` и
  `name` игнорируются (API молча отдаёт общий список). `per_page` игнорируется,
  но `page` работает. Поиск по русскому названию работает, если оно есть в
  `rus_name`/`name`; иначе ищем по английскому/ромадзи.
- `GET /api/manga/{slug_url}` — метаданные: `id`, `rus_name`, `name`,
  `eng_name`, `slug`, `slug_url` (`206--one-piece`), `releaseDateString`
  (`1997 г.`), `cover`, `is_licensed`, `ageRestriction`, `model`.
- `GET /api/manga/{slug_url}/chapters` — `data[]` с `id`, `volume`, `number`,
  `name`, `branches_count`, `branches[]` (`id`, `branch_id`, `teams[].name`,
  `created_at`, `expired_type`). Пагинации нет: у One Piece пришло **1202
  главы** одним ответом (~760 КБ).
- `GET /api/manga/{slug_url}/chapter?volume=1&number=1[&branch_id=…]` —
  `data.pages[]`: `{id, image, slug, url, width, height, chunks, external}`.
  `url` — относительный: `//manga/one-piece/chapters/54644/01.jpg`.
  В ответе есть `bundle`; если `bundle.is_open === false` — том платный,
  страниц нет, показываем понятную ошибку.
- Хосты картинок: `GET /api/constants?fields[]=imageServers`. Для `site_ids`
  с `1` сейчас: `download`/`compress` → `https://img3.cdnlibs.org`,
  `main` → `https://img2.imglib.info`, `secondary` →
  `https://img3.cdnrulib.link`, `crop` → `https://crops.mangalib.me`.
  Порядок в адаптере: `download`, `main`, `secondary`, `compress`, `crop`.
  Fallback — те же `img3`/`img2`, если `/constants` не ответил.
- `img2` в тесте отдал **WebP** при `.jpg` в URL, `img3` — JPEG. Расширение
  берём из `Content-Type`, как у ComX, а не из URL.
- Referer для картинок не обязателен, но с ним работает; отправляем
  `User-Agent`, `Accept: image/...`, `Referer: https://mangalib.me/`.
- `X-RateLimit-Limit: 100` в минуту у API. Держим 700 мс между запросами
  (~85/мин, как у DownloadLib) и 80 мс между картинками.

### Что делает адаптер

`server/src/mango/mangalib.js`:

- `parseMangaLibUrl` / `isMangaLibUrl` — `mangalib.me`, `mangalib.org`,
  поддомены, API-URL, голый slug. Ссылка на читалку тоже принимается: тайтл
  определяется по `/manga/{slug}`.
- `resolveMangaLib` — детали + главы, `seriesKey = mangalib:{id}`, название
  `rus_name` → `name` → `eng_name`, год из `releaseDateString`.
- `chapterFromApi` — `volume`/`number` (пустые → `1`), `name` → папка
  `«номер»` или `«номер - название»`, группа из `branches[].teams[]`.
  Одна глава = одна основная ветка; дубли `volume|number` схлопываются.
- `chapterImages` — запрос главы, сортировка страниц по `slug`, хосты из
  `/constants`, `pagePath`/`imageUrl`, fallback на зеркала.
- `fetchImage` — перебор хостов, 3 попытки, проверка `Content-Type` и размера.

Никакого Chromium: ни при старте сервера, ни при разборе MangaLib. Это
принципиально: браузер остаётся только для ComX.

**Рекомендация (реализовано):** прямой HTTP-адаптер на Node, без расширения и
без браузера. При 403/DDoS-Guard показываем ошибку и ждём; fallback на headless
Chromium не включаем, пока он не понадобится на практике — иначе любой сбой API
будет молча поднимать тяжёлый браузер.

### Решения

1. **Авторизация.** Публичные тайтлы — без токена. Платные закрытые тома
   (`bundle.is_open === false`) не качаем: в задании будет понятная ошибка.
2. **Зеркала.** `mangalib.me` / `mangalib.org`; `seriesKey` — по числовому
   `id` (`mangalib:206`), а не по slug: id стабильнее, slug может меняться.
3. **Ветки.** `branches[]` уже содержит варианты перевода; берём основную ветку
   (`id` главы), группу показываем в tooltip. Отдельного выбора ветки в UI пока
   нет — это следующий шаг, если понадобится.
4. **Платные/недоступные.** `bundle.is_open === false` → ошибка при скачивании.
   Массово проверять все главы при разборе нельзя: это +1 запрос на главу
   (у One Piece — 1202).
5. **`volume: null`.** `Volume 1`.
6. **Название.** `rus_name` → `name` → `eng_name`; год — первые 4 цифры
   `releaseDateString`. Обложку не качаем.
7. **Слаг.** Принимаем `.../ru/manga/206--slug` и `.../manga/206--slug`, API
   зовём по `slug_url` из ответа. Если в ссылке только `slug` без id — API
   тоже понимает, но `seriesKey` всё равно по числовому id из деталей.
8. **Поиск.** Отдельного поиска MangaLib в UI пока нет; можно добавить позже
   (`/api/manga?q=…&site_id[]=1`).

## 7. Пайплайн скачивания

### Задание

- **1 задание = 1 пачка глав одного тайтла** (одна карточка в интерфейсе).
- Внутри задания главы качаются последовательно; страницы — тоже
  последовательно (щадим CDN и не устраиваем 20 параллельных запросов).
- Глобально одновременно живёт ограниченное число манга-заданий (сейчас — по
  одному на тайтл, но разные тайтлы могут стартовать параллельно; стоит
  добавить общий лимит 1–2).
- Прогресс: `done / total`, `current {label, pagesDone, pagesTotal}`,
  `failed[]`; интерфейс опрашивает раз в секунду.

### Частичная глава

- Пишем в `<папка главы>.idk-part`, в конце — атомарный `rename` в финальную
  папку.
- Ошибка/отмена → `.idk-part` удаляется, мусора не остаётся.
- Существующая папка главы = глава скачана. Внутрь не лезем, даже если юзер
  удалил половину страниц: это его контент.
- Докачки по страницам нет: главы маленькие, проще перекачать. (Если станет
  больно — можно сохранять `.idk-part` и продолжать с недостающих.)

### Дубли и повторное добавление

- В БД хранится, какие главы тайтла уже скачаны (`series_key + chapter_id`).
- При новой пачке уже скачанные **молча пропускаются**; недостающие качаются.
- Если всё выбранное уже есть — предупреждение «всё уже скачано», в очередь
  ничего не ставим. Принудительно — только повторным выбором/удалением.
- Диск — истина в последней инстанции: папка есть → глава есть. БД нужна для
  подсчётов и предупреждений.
- Коллизия имени папки у разных тайтлов — суффикс ` 2`, ` 3`.

### Ошибки и повторы

- Ошибка страницы → до 3 попыток с паузой; ошибка главы → глава помечается
  `failed`, задание идёт дальше (одна битая глава не роняет пачку).
- 403/404 на источнике → понятная ошибка; для ComX ссылки на читалку не
  протухают так, как видео, но DleGuard может заартачиться.
- После рестарта сервера незаконченные задания теряются (они в памяти), но
  готовые главы остаются на диске и в БД; повторное добавление их пропустит.
  Это сознательное упрощение; если понадобится — задания в SQLite.

### Что не делаем

- Не качаем обложку, не пишем `ComicInfo.xml`, не пишем метаданные в папки.
- Не делаем CBZ/CBR/PDF.
- Не фильтруем рекламные страницы.
- Не переименовываем и не дописываем уже скачанные главы.
- Не смешиваем языки в одной папке: не-ru главы получают `[en]`; ветки
  переводов пока выбираются одной группой.

## 8. База данных

Текущая таблица:

```sql
CREATE TABLE mango_chapters (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  series_key TEXT NOT NULL,       -- comx:26588
  series_url TEXT NOT NULL,
  series_title TEXT, year TEXT,
  chapter_id TEXT NOT NULL,
  volume TEXT, number TEXT, title TEXT,
  folder TEXT,
  pages INTEGER NOT NULL DEFAULT 0,
  source TEXT,                    -- comx | mangadex
  language TEXT,                  -- ru, en, pt-br…
  group_name TEXT,                -- сканлейт-группа MangaDex
  chapter_url TEXT,
  is_external INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  UNIQUE(series_key, chapter_id)
);
```

Рядом — стабильная папка тайтла:

```sql
CREATE TABLE mango_series (
  series_key TEXT PRIMARY KEY,    -- comx:26588 / mangadex:uuid
  source TEXT NOT NULL,
  url TEXT NOT NULL,
  title TEXT,
  year TEXT,
  folder TEXT NOT NULL,           -- выделенная папка, не пересчитывается
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

Как работает:

- первый раз папка выбирается из `{Название} [{год}]`;
- если папка занята другим `seriesKey` — ` 2`, ` 3` (первый свободный);
- при следующем resolve папка берётся из `mango_series`, даже если тайтл
  переименовали на сайте;
- `deleteSeries` удаляет и строку, чтобы после полного удаления можно было
  начать заново; `deleteVolume` строку не трогает.

## 9. Интерфейс и API

### Веб-морда

- Вкладка «Манга».
- Поле «Ссылка на тайтл» + кнопка «Добавить». Источник определяется по URL.
- После разбора: название, год, источник, количество глав, сколько уже скачано.
- Главы сгруппированы по томам, сворачиваются; чекбоксы по главам и по тому;
  кнопки «Все» / «Только новые» / «Снять всё».
- Для MangaDex — чипы языков из `availableTranslatedLanguages` (не
  захардкоженные ru/en), выбранный язык подсвечен; external-главы помечены
  «на сайте», недоступные — «недоступно»; имя группы — в tooltip.
- Очередь: карточка задания с прогрессом по страницам, пауза/отмена/удаление.
- История: скачанные главы по тайтлам, удаление тома/произведения.
- Подпись: `Cover.png` кладёт юзер; уже скачанные главы пропускаются.

### API (текущий)

| Метод | Что делает |
|---|---|
| `POST /api/mango/resolve` | `{url, language?}` → тайтл + главы с `downloaded`/`pending`; `languages` — для чипов |
| `POST /api/mango/download` | `{url, chapters:[id], language?}` → задание или `job:null`, если всё есть |
| `GET /api/mango/jobs` | живые задания + `stats.chapters` |
| `GET /api/mango/jobs/:id` | полное задание с главами |
| `GET /api/mango/history` | последние скачанные главы |
| `POST /api/mango/jobs/:id/cancel` | отменить задание |
| `POST /api/mango/series/:key/pause` \| `resume` \| `cancel` \| `delete` | управление тайтлом |
| `POST /api/mango/series/:key/volume/:volume/delete` | удалить том |

В ответах уже есть `source`, `sourceLabel`, `language`; у MangaDex — `group`,
`external`, `unavailable`. URL в `resolve` принимает ссылки ComX, MangaDex и
MangaLib.

## 11. Открытые вопросы

1. **Языки MangaDex.** Уже есть чипы и суффикс `[en]`; осталось решить, что
   делать с языками, где только external/пустые главы: показывать чип с
   ошибкой при клике или прятать. Сейчас показываем все из
   `availableTranslatedLanguages`.
2. **Дубли групп.** Выбирать одну группу автоматически или показывать список?
   По какому приоритету (дата, группа, количество страниц)? В тесте у Kaguya
   две группы дали 17 и 19 страниц на один номер — «больше страниц» не всегда
   значит «правильнее».
3. **MangaLib fallback.** Прямой API работает с браузерными заголовками, но
   DDoS-Guard может включиться. Показываем ошибку 403; fallback на Chromium
   включать только если это станет постоянным, иначе любой сбой API будет
   поднимать тяжёлый браузер.
4. **MangaDex@Home report.** Отчёт `POST api.mangadex.network/report` —
   обязательное требование. Делать его на каждую картинку (лишний запрос) или
   пачкой? Если сервер недоступен, не блокировать скачивание.
5. **Общий лимит манга-заданий.** Сейчас разные тайтлы могут качаться
   параллельно; стоит ли 1–2 одновременно?
6. **Рестарт сервера.** Оставляем задания в памяти (теряются) или переносим в
   SQLite?
7. **Оншоты без номера.** `1` — ок или лучше `0`/`Без номера`?
8. **Локальные обложки.** Точно не качаем? Для MangaDex обложка официальная и
   качественная; может, опциональная кнопка «скачать обложку», но не
   автоматически.
