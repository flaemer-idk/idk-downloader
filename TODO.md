## Сделано (для справки)

- **Манга: com-x.life, MangaDex и MangaLib.** Вкладка «Манга» в веб-морде:
  вставил ссылку → сервер разобрал тайтл → главы с галочками → скачивание в
  `{Название} [{год}]/Volume N/глава/000.ext`. ComX открывается в безголовом
  Chromium (DleGuard пропускает только настоящий браузер) и только на время
  разбора; MangaDex и MangaLib — через API без браузера. У MangaDex языковые
  чипы: языки приходят из `availableTranslatedLanguages`, по умолчанию ru,
  не-русские главы получают суффикс `[en]`. MangaLib идёт через
  `api.imglib.info` (резерв `api.cdnlibs.org`), картинки — с `img3.cdnlibs.org`
  и зеркал; платные закрытые тома показывают понятную ошибку. Уже скачанные
  главы пропускаются (история в БД + папка на диске), всё-скачано —
  предупреждение; частичная глава живёт как `.idk-part`; расширение — по
  `Content-Type`. Код — `server/src/mango/`, тесты — `server/test/mango.test.mjs`,
  `server/test/mangadex.test.mjs` и `server/test/mangalib.test.mjs`, дизайн —
  [`mango.md`](mango.md). Chromium ставится Nix-модулем (опция `chromium`),
  путь можно задать в настройках/`CHROMIUM_PATH`. Папка тайтла закрепляется за
  `seriesKey` в `mango_series`: переименование на сайте её не меняет, коллизии
  имён получают суффикс ` 2`, ` 3`.
- **Полигон фронтенда без бэкенда.** `frontend-playground/` — полная копия
  `server/public/` с `mock-api.js`: очередь, история, Mango и настройки
  работают на демо-данных, состояние живёт в `localStorage`. Есть сценарии
  MangaLib (том 6 — 12 глав, том 7 — 8) и MangaDex (6 — 10, 7 — 10), ручной
  редактор томов с каскадом (61–62 → 7, 67 → 6 и т.п.), пауза задания на время
  переноса и счётчик «перемещённых файлов». History/Mango прячет список томов
  под `Volumes · N chapters`. В настройках — конструктор категорий с 16+/18+
  (томатные папки), таблица «как сервер понимает тип» и макет Rezka cookies.
  Add by link разбирает ссылку во франшизу/закладки и показывает карточки с
  качеством, озвучкой, сериями и «скачать заново». Запуск — статический сервер, без `node src/index.js`. Подробности —
  `frontend-playground/README.md`; что переносить в бэкенд — в
  `frontend-playground/PORTING.md`.
- **Реальное разрешение файла на сервере.** `real_width` / `real_height` из
  `prepareTask` (`server/src/tasks.js`) хранятся в БД (колонки `real_width`,
  `real_height` + миграция старых баз), уходят в API (`realWidth`, `realHeight`)
  и показываются в веб-морде рядом с качеством: `1080p → 720p`, если подпись
  врёт. Очередь и история — файловые строки, у истории ещё отдельная пометка
  качества.
- **Проверка свободного места.** Расчёт живёт на сервере (`server/src/estimate.js`,
  `GET /api/state → server.needBytes / needUnknown / placeholderBytes /
  spaceEnough`), а не в браузере: считаются **все** незаконченные задачи минус уже
  скачанное, неизвестный вес берётся по среднему, а без истории — как заглушка
  1.5 ГБ. Место (`freeSpace`) считается по папке, куда файлы реально пишутся
  (`saveDir` = медиатека, если она настроена, иначе папка загрузок) — раньше
  число относилось к папке загрузок и могло «врать», если качалось в медиатеку.
  Расширение предупреждает до отправки партии (кнопка «Всё равно скачать») и
  после ответа сервера; веб-морда — в KPI «Осталось» и в сайдбаре.
- **`storage.sync` для настроек расширения.** Адрес сервера и токен лежат в
  `storage.sync` и в `storage.local` (копия на случай, если синхронизация
  выключена); при загрузке побеждает копия с более свежим `updatedAt`. Старые
  настройки из `storage.local` переносятся сами.
- **Протухшие ссылки.** Перерезолвить на сервере нельзя — у него нет сессии
  сайта (антибот отдаёт ему страницу проверки), а вкладку вы закрываете. Зато у
  каждой задачи хранится страница-источник (`referer`), и её название в
  веб-морде (очередь, история, заголовок группы) и в попапе — ссылка на эту
  страницу. У задачи с ошибкой вида 4xx рядом появляется подсказка: открыть
  страницу → «Скачать» в расширении → задача уходит с новой ссылкой.
- **Озвучка, качество и субтитры по умолчанию.** Попап сам выбирает дубляж (если
  дубляжа нет — озвучку сайта: hdrezka часто ставит активной свою) и качество
  «1080p Ultra» → «1080p». Выше 1080p сам не поднимается, при бедном наборе
  берёт ближайшее снизу; если у дубляжа нет ссылок для серии — возвращается на
  озвучку сайта и говорит об этом. Субтитры, если русские у озвучки есть, качаются
  сразу и на русском (русских нет — галочку не ставим). Проба веса и разрешения
  идёт только по качествам 720p и выше (360p/144p — мусор, а каждая проба —
  Range-запрос). Правила — в `client-extension/defaults.js` (чистые функции, без
  DOM и `chrome.*`), поэтому они и проводка попапа покрыты тестами (см. ниже).
- **Отмена задач одного фильма.** В блоке «уже скачивалось» появилась кнопка
  «Отменить этот фильм» (подтверждение вторым кликом): отменяет незаконченные
  задачи этого фильма — искать их в общей очереди не нужно. Готовые файлы и
  история не трогаются, `.part` удаляется, отменённые задачи возвращаются кнопкой
  «Повторить». Сервер: `downloader.cancelMovie` + `POST /api/movies/:movieId/cancel`
  (отдаёт ещё и свежую сводку, чтобы попап перерисовал счётчики).
- **Тесты.** `cd server && npm test` — расчёт места, работа с БД (миграции,
  приём `real_width`/`real_height`) и отмена задач фильма (`cancelMovie`: свои
  незаконченные отменяются, чужие и готовые — нет, `.part` убирается).
  Расширение — три файла в `client-extension/test/`: `defaults.test.mjs` (правила
  выбора), `popup.test.mjs` (проводка попапа: `vm` + мини-DOM + стабы `chrome.*`)
  и `probe.test.mjs` (нужен `ffmpeg`).

## Кэш пробы качества (объяснение, менять не нужно)

Попап пробует каждое качество 720p и выше Range-запросом и кладёт результат в
`storage.local` под ключом `idk-probe-cache` (до переименования — `hdzg-probe-cache`) на 12 часов (см. `CACHE_KEY` и
`CACHE_TTL_MS` в `client-extension/media-probe.js`). Кэш устроен по-честному:
ключ — сама ссылка на файл, поэтому он работает, только если ссылка совпала
буквально (после перезагрузки страницы hdrezka выдаёт новые подписанные ссылки,
и кэш промахивается). Так что кэш — подстраховка от повторных проб в рамках
одной сессии, а не «источник устаревших данных»: если ссылка протухла, её нет в
кэше, и проба пойдёт заново. Размер кэша не растёт бесконечно: записи пишутся
поверх старых, данные старше TTL игнорируются.

## 1. Мелочи по расширению

- Список качеств рисуется своим контролом (в `<option>` бейдж не вставить); в
  строку можно добавить ещё и кодек — проба его уже возвращает
  (`probe.codec` → `CODEC_LABELS`).
- Скорость пробы: на одно качество уходит 1–3 Range-запроса (128 КБ, потом обход
  верхнеуровневых боксов до `moov`, если файл без faststart). У большинства
  файлов `moov` лежит в конце, поэтому можно читать ещё и хвост (последние ~2 МБ)
  и искать `stsd`/`tkhd` там — запросов станет меньше. Мусорные качества (ниже
  720p) уже не пробуются вовсе, см. выше.
- Скорость и оставшееся время в попапе: сервер отдаёт `receivedBytes`/
  `totalBytes`, скорость считается по разнице между опросами (в веб-морде это
  уже сделано — `updateSpeeds` в `server/public/app.js`), в попапе — только
  проценты.
- Уведомление о конце партии: сейчас о завершении 20 серий узнаёшь, только
  открыв попап или веб-морду.
- Фильтры «не скачивать премиум» / «пропускать CAMRip»: есть только звёздочка
  премиума без фильтрации.
- Премиум-заглушка: сайт отдаёт для премиум-контента файл ровно 8 554 559 байт.
  Проба уже знает вес — можно определять по размеру и показывать «премиум, файла
  нет» вместо «Скачать» (в оригинальном расширении это сделано). Как только
  появится определение, стоит подумать и о выборе по умолчанию: сейчас премиумное
  «1080p Ultra» выбирается как обычное (по умолчанию предпочитается дубляж без
  пометки премиума, а вот качество премиум не фильтруется).

## 2. Сервер

- Если файл уже лежит на диске, разрешение можно уточнять через `ffprobe` — но
  обычно не нужно: клиент присылает данные бесплатно.
- SSE/WebSocket вместо опроса `/api/state` раз в секунду (при большом числе
  задач), управление порядком очереди, лимит скорости.
- Хранилище куки для серверного резолвера — тогда сервер смог бы сам
  перерезолвить протухшую ссылку, когда Cloudflare не мешает (или при
  подключённом FlareSolverr). Пока надёжнее путь через расширение.
